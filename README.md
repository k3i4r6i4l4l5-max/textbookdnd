# Архив Доски

Локальная энциклопедия авторского фэнтезийного мира: React, TypeScript, Vite, Tailwind CSS 4, React Router и Lucide React. Без сервера данных, авторизации и панели редактирования. Посетители читают сведения; разработчик изменяет JSON в проекте.

## Запуск и проверки

Node.js 20.19+ или 22.12+ и npm.

```sh
npm install
npm run dev
```

Открыть адрес Vite, обычно http://127.0.0.1:5173/.

```sh
npm run check:characters
npm run build
npm run preview
```

`build` проверяет TypeScript, выполняет проверки данных и фильтрации, затем собирает сайт в `dist/`. Проверки каталога используют Vite без запуска HTTP-сервера. `preview` показывает production-сборку локально.

## Страницы

- `/` — главная с переходами в «Персонажи», «Мир» и «За Доской».
- `/characters` — единый каталог всех персонажей с независимыми фильтрами по стороне, атрибутам и ролям.
- `/characters/:id` — постоянная страница персонажа. Перенос JSON в другую папку или смена роли не меняют адрес.
- `/world` — категории мира и справочник атрибутов, включая Ведьминский фактор.
- `/beyond` — тематические переходы в каталог: «Чудотворцы и наблюдатели» и «Ведьмы и Территориальные Лорды».

Старый `/figures` перенаправляет в `/characters`. Старые категории `/beyond/observers` и `/beyond/witches` перенаправляют в каталог с соответствующими ролями. Старые ссылки `/beyond/:category/:id` ведут на `/characters/:id`.

Фильтры сохраняются в адресе, например:

```text
/#/characters?side=white&attribute=star&role=territorial-lord
```

Внутри группы достаточно совпадения с одним выбранным значением, между группами должны совпасть все условия. Например, белый территориальный лорд с атрибутом Звезды попадёт в эту выборку. Персонаж с неизвестными атрибутами не совпадает с фильтром конкретного атрибута. Пустая группа означает «Все». Можно сбросить одну группу или все фильтры. При открытии персонажа и возврате в каталог выбор сохраняется.

Если выбрана только белая сторона, применяется белая тема с чёрным текстом и голубоватым свечением; только чёрная — чёрная тема с белым текстом и красным свечением; нейтральная и неизвестная — серо-серебряная. Нейтральная сторона (`neutral`) и неизвестная (`unknown`) — разные фильтры. Несколько сторон или «Все» используют исходную палитру архива. Страница персонажа использует его сторону, независимо от ролей. Поддерживается `prefers-reduced-motion`.

## Где редактировать персонажей

Все записи лежат в одной папке. Одна запись — один JSON-объект в отдельном файле, без индексов и служебных файлов рядом:

```text
src/data/characters/
  White/Sei.json
  White/battler.json
  Black/dante.json
  Black/faal.json
  Neutral/ange.json
  Neutral/...
  Watchers/jester.json
  Witches/...
  Wonderworkers/...
```

Можно создавать вложенные папки для своего удобства: JSON из них тоже загрузятся автоматически. Папка больше не определяет сторону, роли или каталоги. Не копируйте одного персонажа в разные файлы: его `id` должен быть уникальным во всей коллекции.

Пример структуры записи (иллюстрация формата, не дополнительный персонаж):

```json
{
  "id": "example",
  "name": "Имя персонажа",
  "image": "characters/example.png",
  "side": "white",
  "roles": ["observer", "territorial-lord"],
  "personality": "chaotic-neutral",
  "affiliation": "Название организации",
  "knownInfo": "Известные сведения.\nСледующий абзац.",
  "attributes": ["void", "star"],
  "artifacts": [
    {
      "id": "example-artifact",
      "name": "Название артефакта",
      "image": "artifacts/example.png",
      "description": "Описание предмета"
    }
  ]
}
```

Обязательны `id` и `name`. Остальные поля можно не добавлять. Во всех текущих записях оставлен полный набор полей для удобного заполнения: неизвестный `personality` — `null`, незаполненные текстовые поля — `""`, неизвестные `attributes` и `artifacts` — `null`. Заполненные сведения сохранены. В JSON нельзя писать комментарии, использовать `undefined` и ставить запятую после последнего поля.

- `id` — строчные латинские буквы, цифры и дефисы. Определяет адрес страницы. Имя файла может отличаться, но удобнее называть его по `id`.
- `image` — путь относительно `public/`, без слова `public/`. Изображения продолжают храниться в `public/characters/`; загрузчик добавляет базовый путь сайта. Это касается и изображений артефактов. Пока портрет не указан или не загрузился, показывается заглушка.
- `side` — `white`, `black`, `neutral` или `unknown`. Без поля сторона считается неизвестной. Она не определяется моральным характером, ролью или организацией.
- `roles` — любое количество значений из таблицы ниже. Белый персонаж может одновременно быть наблюдателем и лордом. `[]` или отсутствие поля означает, что роли пока не заданы.
- `personality` — один из девяти идентификаторов в `src/data/alignments.ts` либо `unknown` (неизвестен), `not-applicable` (неприменимо), `null` (ещё не заполнен). Специальные статусы имеют серое обозначение и не входят в шкалу девяти характеров. Отображается цветным обозначением от зелёного до багрового; доступна легенда.
- `affiliation` — произвольный текст принадлежности к организации или группе. Это отдельное поле, оно не назначает роли автоматически.
- `knownInfo` — текст столбца «Что известно:». Переносы строк задаются через `\n`. Без текста показывается «Пока нет записей.».
- `attributes` — массив идентификаторов из `src/data/attributes.ts`: `fire`, `earth`, `water`, `air`, `lightning`, `sky`, `darkness`, `light`, `void`, `star`, `witch-factor`. `null` означает явно неизвестные атрибуты и отображается как «?», отсутствие поля — сведения ещё не заполнены.
- `artifacts` — массив объектов с обязательными `id` и `name`; `image` и `description` необязательны. `null` означает неизвестные артефакты. Предметы отображаются в инвентаре; пустые ячейки декоративные и не ограничивают вместимость.
- `description` — необязательное краткое описание, зарезервированное в модели данных.

| Роль | Значение в JSON |
| --- | --- |
| Фигура | `figure` |
| Наблюдатель | `observer` |
| Чудотворец | `wonderworker` |
| Ведьма | `witch` |
| Территориальный лорд | `territorial-lord` |

Новые роли добавляются в `src/data/roles.ts`: фильтры и подписи используют этот единый справочник. Данные проверяются при загрузке и при `npm run build`; ошибки основных полей, неизвестные значения и повторяющиеся id содержат имя файла.

Сведения Jester и Sei сохранены. Для добавленных портретов созданы отдельные JSON: изображения из `White` получили `side: "white"`, из `Black` — `"black"`, из `Neutral` — `"neutral"`. Персонажи из `White`, `Black` и `Neutral` имеют роль `figure`. JSON разложены по подпапкам с теми же названиями, что и папки портретов. Папки `Watchers`, `Witches` и `Wonderworkers` использованы для первоначального назначения ролей; сторона этих персонажей пока неизвестна. Battler представлен одной записью с портретом из `White`; наличие второго изображения в общей папке `Witches and Lords` пока не определяет конкретную роль.

Это первоначальное заполнение данных: после добавления JSON сторона и роли редактируются в нём. Перемещение изображения между папками автоматически их не изменяет; нужно также обновить `image`. Загрузчик находится снаружи папки персонажей — в `src/data/characterLoader.ts`. Проверка каталога проверяет существование указанных локальных портретов.

После изменения JSON на опубликованном сайте нужна новая сборка и публикация. В режиме `npm run dev` Vite обновляет данные автоматически.

## Структура проекта

```text
src/
  app/App.tsx                     маршруты и перенаправления старых адресов
  components/layout/              шапка, подвал, общий макет
  components/ui/                  заголовки, карточки, диалоги, пустые состояния
  components/characters/          фильтры, портреты, атрибуты, характер и инвентарь
  pages/                          главная, каталог, профиль, мир, за Доской
  data/characters/                только JSON персонажей
  data/characters.ts             загрузка общей коллекции и поиск по id
  data/characterLoader.ts         проверка JSON и разрешение путей изображений
  data/characterFilters.ts        чтение фильтров и отбор персонажей
  data/roles.ts                   справочник ролей
  data/beyond.ts                  тематические ссылки в каталог
  data/attributes.ts              атрибуты мира
  data/alignments.ts              девять характеров
  types/character.ts              общие типы персонажей и инвентаря
  styles/globals.css              палитра, адаптивность и анимации
scripts/check-characters.mjs       проверки данных, фильтров и страниц
```

Manrope с кириллицей включён в сборку, fallback — Arial. Золотые эмблемы атрибутов созданы встроенным `image_gen`; WebP 512 × 512 с прозрачностью хранятся в `public/attributes/`, промпты — в `docs/attribute-emblems.json`. В мире названия видны постоянно; у персонажей — при наведении, фокусе и нажатии. Escape закрывает подсказку. Исходные изображения генератора сохранены в стандартном каталоге Codex.

## GitHub Pages

Используется `HashRouter`: адреса вида `/#/characters/sei` работают при прямом открытии и обновлении на статическом хостинге. В Vite задан `base: './'` для размещения в подпапке репозитория.

Публикация из исходников через GitHub Actions:

1. Создайте репозиторий на GitHub и загрузите содержимое проекта в его корень: `package.json`, `package-lock.json`, `index.html`, конфигурацию, папки `src`, `public`, `scripts` и `.github`. Папка `.github` обязательна. Не загружайте `node_modules`, `dist` и `.qa`.
2. В репозитории откройте **Settings → Pages → Build and deployment → Source → GitHub Actions**.
3. Отправьте изменения в `main` или `master`. Либо откройте **Actions → Deploy to GitHub Pages → Run workflow**. Для другой основной ветки измените `branches` в workflow.
4. Дождитесь успешного задания `deploy`: ссылка на сайт появится в нём и в Settings → Pages.

Пример адреса: `https://USERNAME.github.io/REPOSITORY/#/characters`. Имя репозитория не нужно вписывать в исходники. Корневой сайт `https://USERNAME.github.io/` также поддерживается.

Workflow устанавливает зависимости через `npm ci` на Node.js 22, проверяет данные, собирает сайт и публикует только `dist/`. Проверяются портреты, эмблемы и изображения артефактов, включая точный регистр имён файлов. Шрифты включены в сборку. Сервер приложения, ключи API и база данных не нужны.

После редактирования JSON или изображений отправляйте изменения в репозиторий — сайт обновится после успешной сборки. Для локальной проверки: `npm run build`, затем `npm run preview`.

В каталоге проекта сейчас нет `.git`: подготовка файлов не создаёт репозиторий и не публикует сайт автоматически. Не используйте исходную папку как готовую статическую страницу; для ручного хостинга подходит содержимое `dist/`.

### Дополнительные состояния данных

`attributes: []` — персонаж не имеет атрибута; `attributes: "not-applicable"` — неприменимо; `attributes: null` — неизвестно. Эти состояния не совпадают с фильтрами конкретных элементов.

`affiliation` поддерживает строку или массив организаций, например `["Группа Сей", "Titul"]`. В профиле каждая принадлежность отображается отдельно.
